# 1.微程序


$$\mathbf{\text{机器指令}} \longrightarrow \mathbf{\text{微程序}} \longrightarrow \mathbf{\text{微指令}} \longrightarrow \mathbf{\text{微命令 / 微操作}}$$

### 用“做菜”来比喻，秒懂这四个概念：

- **机器指令**（如 `ADD`）：就像**菜单上的一道菜**（比如“宫保鸡丁”）。
    
- **微程序**（Microprogram）：就像**这道菜的完整菜谱**。每一条机器指令都对应一段微程序。
    
- **微指令**（Microinstruction）：就像菜谱里的**每一个具体步骤**（比如“第一步：热锅下油”）。**一条微指令对应 CPU 的一个时钟周期（节拍）**。
    
- **微命令 / 微操作**（Microcommand / Micro-operation）：就像在这个步骤里**手的具体动作**（比如“左手倒油”和“右手开大火”同时发生）。
    
    - ==**微命令**是控制信号（比如 `PCout=1`）==。
        
    - **微操作**是这个信号触发的实际硬件动作（比如“把 PC 的值放上总线”）。
        

### 💡 考场高频对错判断

1. **一条机器指令 = 一个微程序**（对）
    
2. **一个微程序 = 若干条微指令**（对）
    
3. **一条微指令 = 若干个微命令 / 微操作**（对）
    
4. **一条微指令在多个时钟周期内完成**（**错！** 一条微指令**必须且只能在一个时钟周期/节拍内**完成）

## 一、 微程序控制器的核心概念（必考基础）

你要先记住这组**硬件与微程序的对应关系**（非常喜欢出选择题）：

- **机器指令**：写在程序里的指令（如 `ADD R1, R0`）。一条机器指令包含一个**微程序**。
    
- **微程序**：由若干条**微指令**组成（对应一条机器指令的执行过程）。
    
- **微指令**：在一个时钟周期（节拍）内执行的一组微操作命令。包含两部分：
    
    - **操作控制字段**：控制各个微操作（如 `PCout`, `MARin`）。
        
    - **顺序控制字段**：决定**下一条微指令的地址**。
        
- **微操作 / 微命令**：最底层的硬件控制信号（如电平信号）。
    

## 二、 408 核心考点与题型分类

考研中关于微程序控制器的考察，主要集中在以下 **4 个核心板块**：

### 1. 核心硬件部件（名称与作用）

图示经常出现在大题或选择题中，必须死记这几个寄存器：

- **CM（Control Memory，控制存储器）**：存放所有微程序的 ROM（在 CPU 内部，速度极快）。
    
- **CMAR / microPC（微地址寄存器）**：存放**下一条微指令在 CM 中的地址**。
    
- **CMDR / µIR（微指令寄存器）**：存放**当前正在执行的微指令**。
    
- **微指令译码器**：将 CMDR 中的操作控制字段翻译成具体控制信号。
    

### 2. 微指令的编码方式（控制字段怎么设计）★高频计算题

这部分最喜欢考**计算微指令的字长（位数）**：

- **直接编码法（直接控制法）**：
    
    - 每一位代表一个微命令（1 表示有效，0 表示无效）。
        
    - **特点**：速度最快，但**微指令字长太长**，浪费存储空间。
        
- **字段直接编码法（互斥类编码）**：
    
    - 将互斥的控制信号分在同一个字段，相容的控制信号分在不同字段。
        
    - **计算规则**：若一个字段包含 $N$ 个**互斥**微命令，则该字段需要 $\lceil \log_2(N + 1) \rceil$ 位（**必须加 1**，因为需要保留一个状态表示“不发任何命令”）。
        
- **混合编码**：结合直接编码和字段编码。
    

### 3. 后继微地址的形成方式（下条微指令去哪找）

微指令如何找到下一条微指令的地址？有两种主要方式：

1. **断续方式（下地址字段法 / 隐式与显式）**：
    
    - 在当前微指令中专门留出一个 **下地址字段（Next Address）**，直接指出下一条微指令的 CM 地址。
        
2. **通过机器指令的操作码（OP）形成**：
    
    - **取指阶段结束时**，需要根据机器指令的 **OP 码** 找到该指令对应的微程序入口地址（这个过程叫**微地址映射 / 译码**）。
        

### 4. 微指令的格式分类

- **水平型微指令**：
    
    - **特点**：一次可以并行发出**多个微命令**（并行能力强），字长长，微程序短，执行速度快。
        
    - **对应**：类似“并行处理”。
        
- **垂直型微指令**：
    
    - **特点**：一次只能发**一个微命令**（类似微型机器指令），字长短，微程序长，执行速度慢。
        
    - **对应**：类似常规机器指令。
        

## 三、 考场高频坑点总结（一错就扣分）

| **易错点**             | **正确理解**                                                                     |
| ------------------- | ---------------------------------------------------------------------------- |
| **主存 vs 控制存储器(CM)** | **主存**存的是**机器指令和数据**；**CM**存的是**微指令**。CM 在 CPU 内部，是 ROM！                     |
| **PC vs CMAR**      | **PC** 记录下一条**机器指令**的主存地址；**CMAR** 记录下一条**微指令**的 CM 地址。                      |
| **互斥字段编码 $+1$**     | 计算字段编码位数时，**千万别忘了空状态 (+1)**！例如 7 个互斥信号，需要 $\lceil \log_2(7+1) \rceil = 3$ 位。 |
| **取指微程序**           | **所有机器指令共享同一段“取指微程序”**，只有到了执行阶段，才根据 OP 码跳转到各自的微程序。                           |

## 💡 复习建议

微程序控制器在 408 考试中，**选择题**常考“水平型/垂直型对比”、“CM/CMAR 概念”和“互斥字段编码位数计算”；**大题**常考结合数据通路，让你写出某条微指令的控制信号或下地址。

掌握了上述 **4 个核心板块** 和 **互斥编码 $+1$ 规则**，微程序控制器这部分的得分率就能达到 90% 以上！





# 2.控制部件和运算器部件
在 CPU 架构中，**控制器（Control Unit, CU）** 是指挥全局的“大脑”，而 **运算器（ALU）** 是干体力活的“算盘”。

判断一个部件或寄存器是否属于控制部件，核心看它的功能：**它是用来“指挥/控制指令执行”的，还是用来“暂存数据/做数据运算”的？**

### 一、 哪些是控制部件？（Controller Components）

控制部件通常由以下 **5 大核心硬件** 组成：

1. **指令译码器（ID, Instruction Decoder）**
    
    - **作用**：对指令寄存器（IR）里的操作码（OP）进行“翻译”，弄清楚这条指令到底要做加法、减法还是访存，并告诉控制器接下来该发什么信号。
        
2. **微程序控制器核心部件**（如果是微程序控制器）
    
    - **控制存储器（CM, Control Memory）**：存放所有微程序的 ROM。
        
    - **微指令译码器**：将微指令的操作控制字段翻译成具体的电平信号。
        
3. **时序控制信号形成部件 / 时序发生器（Timing Generator）**
    
    - **作用**：产生节拍脉冲（如 $C_1, C_2, C_3\dots$）和时钟信号，确保各个控制信号在正确的时间点发出，防止总线冲突。
        
4. **控制信号形成逻辑 / 控制单元（CU Logic）**
    
    - **作用**：结合指令译码器的输出和当前的时钟节拍，最终产生并输出所有的微命令（控制信号，如 `PCout`, `MARin`, `MemR` 等）。
        
5. **程序状态字寄存器 / 标志寄存器（PSW）**（_注：兼具控制与运算属性，但通常归入控制部分_）
    
    - **作用**：记录条件码（如 $ZF$ 零标志、$CF$ 进位标志），用来控制条件跳转指令（如 `JZ`、`JMP`）。
        

### 二、 哪些寄存器属于控制部件？（控制部件内的寄存器）

在 408 考研和计算机体系结构中，寄存器被明确划分为 **控制器中的寄存器** 和 **运算器中的寄存器**：

#### 属于【控制部件】的寄存器（必背重点）：

1. **PC（Program Counter，程序计数器）**
    
    - **功能**：存放下一条要执行的**机器指令的主存地址**。它是控制程序顺序执行的核心。
        
2. **IR（Instruction Register，指令寄存器）**
    
    - **功能**：暂存当前正在执行的**机器指令**，供指令译码器（ID）进行译码。
        
3. **MAR（Memory Address Register，主存地址寄存器）**
    
    - **功能**：暂存 CPU 要访问的**主存单元地址**。（虽然它连接主存，但在物理划分上归控制器管辖，用于控制访存寻址）。
        
4. **CMAR / $\mu$PC（Microprogram Address Register，微地址寄存器）**
    
    - **功能**（仅微程序控制器）：存放下一条要执行的**微指令在 CM 中的地址**。
        
5. **CMDR / $\mu$IR（Microprogram Data Register，微指令寄存器）**
    
    - **功能**（仅微程序控制器）：暂存当前正在执行的**微指令**。
        

### 三、 避坑对比：哪些寄存器【不属于】控制部件？

为了防止混淆，以下寄存器属于 **运算器（或数据通路数据缓冲）**，不属于控制部件：

- **通用寄存器（$R_0 \sim R_3$、AX、BX 等）**：属于运算器/数据通路，用来存操作数和中间结果。
    
- **MDR / MBR（主存数据寄存器）**：属于数据通路，用来暂存从主存读写的数据。
    
- **暂存器 T / 累加器 AC**：属于运算器，用于锁存 ALU 的输入或输出数据。
    
- **移位寄存器 SR**：属于运算器，用于做数据移位。
- 状态条件寄存器
    

### 💡 考场一秒区分法

> - 只要名字或功能和 **“指令”、“地址”、“微程序”、“程序流程”** 挂钩的（**PC, IR, MAR, CMAR, CMDR**），全都是 **控制部件/控制器寄存器**！
>     
> - 只要是纯粹用来 **“存数”、“算数”、“数据中转”** 的（**$R_0\sim R_3$, MDR, T, AC, SR**），全部归 **运算器/数据通路**！


# 3.公共取指指令


$$\text{一条机器指令的完整微程序} = \underbrace{\text{公共取指微程序}}_{\text{取指阶段}} + \underbrace{\text{该指令专有的微程序}}_{\text{执行阶段}}$$



### 1. 概念不同：“机器指令” vs “微指令”

- **机器指令 ：是程序员在写汇编/代码时调用的指令（比如写了 32 种不同功能的指令：加法、减法、乘法、跳转等）。
    
- **取指（Fetch）**：是 CPU 内部为了**把你的代码从内存拿进 CPU** 而固化在硬件里的**动作**。
    

在 CPU 硬件眼里，不管你要做这 32 种里的哪一种，**第一步都必须先把代码从内存读出来**。

### 2. 假设“取指”算作一条指令，逻辑会彻底崩溃

我们来反推一下：假设我们把“取指”算作第 33 条（或者这 32 条机器指令里的其中一条，假设叫 `FETCH`）：

1. **谁来调用 `FETCH`？**
    
    在程序执行时，编译器或程序员不可能在每行代码前都手动写一条 `FETCH` 机器指令。
    
2. **死循环陷阱（鸡生蛋、蛋生鸡）：**
    
    如果你把“取指”做成一条机器指令，CPU 要执行 `FETCH` 之前，**硬件依然需要先“取”这条 `FETCH` 指令本身**！这就陷入了死循环。
    

==所以，“取指”不能作为一条独立的机器指令存在，==它必须是 CPU 控制器**天然自带、强制执行的硬件控制流程**。

$$\text{总微指令数 } N = \text{公共取指微指令数} + \sum (\text{各机器指令执行阶段微指令数})$$








# 4.异常和中断



## 一、 核心区别：什么时候检测？

|**类型**|**触发源**|**检测时机（最核心考点）**|**典型例子**|
|---|---|---|---|
|**中断 (Interrupt)**|**CPU 外部**<br><br>  <br><br>(网卡、键盘、定时器等)|**指令执行周期的末尾（CPU 准备取下一条指令前）**<br><br>  <br><br>CPU 在每条指令执行完的末尾检查中断请求线（INTR/NMI）。|键盘按下、磁盘 DMA 读写完成、定时器到期|
|**异常 (Exception)**|**CPU 内部**<br><br>  <br><br>(执行当前指令时产生)|**随指令执行实时检测（随时/特定微程序节拍）**<br><br>  <br><br>在指令执行过程中，一旦硬件电路检测到异常条件（如除零、缺页），**立即中断当前指令**。|除以 0、地址越界、缺页异常、溢出、非法指令|

## 二、 详细检测时机拆解

### 1. 外部中断：为什么只在“指令执行末尾”检测？

外部中断是**异步**的（随时可能发生）。但为了保证计算机执行指令的**原子性**（保证一条指令要么完整执行完，要么还没开始），CPU **不会在指令执行到一半时理会外部中断**。

- **检测过程**：
    
    1. 在一条指令的最后一个时钟周期（节拍），CPU 的控制逻辑会去采样 **中断请求引脚（INTR / NMI）**。
        
    2. 如果有中断请求，且 CPU 此时处于 **开中断（IF=1）** 状态，CPU 就会进入 **中断周期（Interrupt Cycle）**，暂停下一条指令的取出，转去处理中断。
        

### 2. 异常：为什么是“执行过程中实时”检测？

异常是**同步**的，是由当前正在执行的这条指令“自己引发”的。它不需要等指令执行完——**因为指令本身已经无法正常执行下去了**！

- **发生在取指/译码阶段**：如检测到“非法指令码”或“指令地址越界”。
    
- **发生在执行阶段（ALU）**：如执行 `DIV` 指令时发现除数是 0，或者加法指令发生了溢出。
    
- **发生在访存阶段（MEM）**：如执行 `LOAD/STORE` 指令时发现访问的虚页不在内存中（**缺页异常**）。
    

一旦硬件检测到上述条件，当前指令的后续写回操作（WB）会被**强制取消**，立即抛出异常。

## 三、 异常与中断的完整硬件处理过程

无论是异常还是中断，一旦检测成功，CPU 就会硬件自动进入 **中断/异常响应周期**。整个处理过程分为 **硬件硬件完成（中断隐指令）** 和 **软件（中断服务程序）完成** 两部分：

Plaintext

```
[检测到中断/异常]
       │
       ▼
┌──────────────┐
│  中断隐指令  │ ◄─── 1. 关中断（IF = 0）
│ (硬件自动完成)│      2. 保存断点（PC 和 PSW 压栈/存入专用寄存器）
└──────┬───────┘      3. 引出中断服务程序入口地址（向量中断/中断向量表）
       │
       ▼
┌──────────────┐
│中断服务程序  │ ◄─── 1. 保存现场（保存通用寄存器内容）
│(软件/操作系统)│      2. 执行具体的中断/异常处理逻辑
└──────┬───────┘      3. 恢复现场（恢复通用寄存器）
       │              4. 中断返回指令（IRET/RTI），开中断，恢复 PC
       ▼
[返回原程序或调度新程序]
```

## 四、 考场高频坑点总结（一错就扣分）

1. **“中断隐指令”是不是一条真正的指令？**
    
    - **不是！** 它不是程序里写的机器指令，而是 CPU 在检测到中断/异常后，**由 CPU 硬件电路自动执行的一组微操作**（例如压栈 PC、修改 IF 标志等）。
        
2. **断点（PC）存的是哪一条指令的地址？**
    
    - **中断（External Interrupt）**：通常存的是 **下一条** 待执行指令的地址（因为当前指令已经顺利执行完了）。
        
    - **可修复异常（如缺页异常）**：存的是 **当前产生异常的这条指令本身的地址**！因为处理完缺页（把页从磁盘调入内存）后，还需要**重新执行**这条访存指令。
        
    - **不可修复异常（如致命错误/终止）**：直接终止程序，不再返回。
        
3. **中断检测条件**：
    
    - 必须同时满足：**有中断请求线信号** + **CPU 允许中断（开中断状态 IF=1）** + **当前处于指令周期的末尾**。



|**对比维度**|**Cache 缺失 (Cache Miss)**|**缺页异常 (Page Fault)**|
|---|---|---|
|**性质划分**|**硬件事件 / 硬件流水线阻塞**|**内部中断 / 软件可修复异常**|
|**处理者**|**Cache 控制器（纯硬件）**|**操作系统 OS 内核（软件）**|
|**处理耗时**|几个到几十个 CPU 时钟周期|数百万个时钟周期（涉及到磁盘 I/O）|
|**CPU 状态切换**|**不切换**（保持在当前用户态/内核态）|**必须切换**（从用户态切换到内核态）|
|**是否触发中断隐指令**|**否**|**是**|
- **除以零、地址越界、溢出、缺页、非法指令** $\implies$ **全都是异常（Exception）**。
    
- **Cache 缺失（Cache Miss）、TLB 缺失（TLB Miss）** $\implies$ **都不算异常！**
    
    - _注：TLB 缺失在绝大多数现代架构（如 x86）中也是由硬件 MMU 自动刷新填充的，不算异常；只有在少数纯软件管理 TLB 的架构（如 MIPS）中，TLB 缺失才会触发专门的硬件异常来让 OS 填表，但在 408 的通用考查中，**默认把 Cache/TLB 缺失看作硬件级的 Miss，不归为 OS 级别的异常**。_

| **终止 (Abort)** | 主存奇偶校验错、控制器硬件故障     | **不返回**   | **随机 / 发生故障时的 PC** | 程序直接终止，断点仅用于记录日志/报告错误。   |
#### 存储保护错

在现代操作系统中，为了防止进程之间互相破坏或者用户程序篡改内核数据，硬件（MMU）和操作系统设置了存储保护机制：

1. **写保护（Write Protection）**：试图向**只读页面**（例如代码段 `.text` 或只读常量段）执行写入操作（如执行 `STORE` 指令）。
    
2. **越界错 / 越限错（Limit Fault）**：访问的逻辑地址（或页表项）超出了当前段/页的上限（例如访问了未经分配的野指针地址）。
    
3. **权限违规（Privilege Fault）**：用户态（User Mode）程序试图访问内核态（Kernel Mode）专用的内存地址。

当 CPU 执行某条访存指令，发现**违反了上述任意一条规则**时，MMU（内存管理单元）就会硬件报错，抛出 **“存储保护错”**。



# 5.流水线冒险



## “寄存器堆的半周期读写”

它是解决**写后读（RAW, Read After Write）数据冒险**最经典、成本最低的硬件手段之一！


```
               ┌─────────────────────── 一个完整的 Clock Cycle ───────────────────────┐
               │                                                                      │
               ├──────────────────────────┬───────────────────────────────────────────┤
               │   前半周期（前半拍）     │            后半周期（后半拍）            │
               ├──────────────────────────┼───────────────────────────────────────────┤
硬件动作       │  前一条指令进行【写操作】 │  后一条指令进行【读操作】                 │
流水线阶段     │  (指令1 的 WB 阶段写 R1) │  (指令2 的 ID 阶段读 R1)                  │
               └──────────────────────────┴───────────────────────────────────────────┘
```

1. **前半周期（写）**：
    
    上一条处于 WB 阶段的指令（`ADD`），在时钟周期的前半段，把计算结果**快速写入**通用寄存器 `R1`。
    
2. **后半周期（读）**：
    
    下一条处于 ID 阶段的指令（`SUB`），在同一个时钟周期的后半段，去**读取** `R1`。此时 `R1` 里面的值**已经被前半周期的操作更新过了**！
    

**结果**：下一条指令成功读到了最新的正确数据，**零延迟、零气泡**地解决了这种时间冲突！

### 三、 考场避坑：这种方法能解决“所有”数据冒险吗？

**不能！** 这是一个非常高频的选择题坑点：

- **能解决的场景**：
    
    只能解决同周期重叠的写后读（RAW）问题（即上一条指令已处于 WB 阶段，下一条指令处于 ID 阶段）。
    
- **解决不了的场景（Load-Use 冲突）**：
    
    如果上一条指令是 **`Load`（如 `LW`）** 指令，它的数据要等 **MEM 阶段（第 4 周期）** 结束后才能从主存/Cache 里拿出来。
    
    - 此时下一条指令在 **ID 阶段（第 3 周期）** 就想要数据，**连写都还没写呢**，半周期读写也无能为力！
        
    - **结论**：对于 `Load-Use` 冲突，**必须插入 1 个周期的空置气泡（Stall）**，然后再配合转发/半周期读写才能拿到数据。
        

### 💡 考场总结

1. **半周期读写**：**前半周期写，后半周期读**。
    
2. **核心作用**：消除了“同一周期内，前指令 WB 写寄存器，后指令 ID 读同一寄存器”的数据冲突。
    
3. **408 默认设想**：在很多 408 经典数据通路大题中，默认都**隐含了这个硬件假设**（即同一周期内先写后读，可直接拿到新值）。

## 控制冒险

    

## 一、 为什么很多题目/架构把确定时机定在 M 阶段？

### 1. PC 更新与控制线的硬件锁存周期

虽然 ALU 在 EX 阶段算出了“要不要跳”以及“跳到哪里”，但出于硬件同步的考量：

- 标志寄存器（如 Z/N 位）或比较结果需要经过 EX/MEM 流水线寄存器保存。
    
- 在典型的 5 段流水线中，**控制信号和新 PC 的写回（写入 PC 寄存器）往往统一放在 M 阶段甚至 WB 阶段的开始**。
    
- 如果设计规定“统一在 M 阶段更新 PC”，那么硬件必须等 M 阶段信号稳定后，才能把新的 PC 赋过去，此时 IF 阶段才能去取真正目标地址的指令。
    

### 2. 考虑“间接跳转”指令（如 `JR` 或带访存的 Jump）

- 如果是一般的分支指令（如 `BEQ`），目标地址是 $PC + \text{立即数}$，EX 阶段就能算出。
    
- 但如果是**==通过内存进行间接跳转==**的指令（比如某些架构支持从内存单元里读出跳转目标地址）：
    
    - EX 阶段只算出了内存地址；
        
    - **必须到了 M 阶段去读取存储器**，才能真正拿到跳转的目标 PC！
        
    - 为了简化 CPU 控制逻辑，很多流水线把所有转移指令的控制点**统一对齐到了 M 阶段**。
        


|**确定阶段**|**硬件要求 / 场景**|**预测失败损失（Penalty）**|
|---|---|---|
|**ID 阶段**|专门将比较逻辑和地址加法器**前移至 ID 阶段**。|仅需冲刷 **1 个** 周期（IF 误取的那条）。|
|**EX 阶段**|标准 5 段流水线（利用 EX 阶段的 ALU 计算）。|需要冲刷 **2 个** 周期（IF、ID 误取的那两条）。|
|**MEM 阶段**|题目设定在 M 阶段更新 PC，或包含访存跳转。|需要冲刷 **3 个** 周期（IF、ID、EX 误取的三条）。|

### 💡 总结

> **不是 EX 算不出来，而是硬件“何时把新 PC 真正写回并生效”决定了流水线何时能知道。**
> 
> 算出来（EX 阶段） $\neq$ 写入 PC 并让取指单元拿到（可能延迟到 M 阶段）。做题时按题干给的数据通路结构来计算流水线气泡即可！
