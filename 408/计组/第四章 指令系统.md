# 3.sf of判断

| **SF** | **OF** | **SF⊕OF** | **逻辑意义**          | ==**x>0 是否成立？==(假设 ZF=0)** | **典型场景**                   |
| ------ | ------ | --------- | ----------------- | -------------------------- | -------------------------- |
| **0**  | **0**  | **0**     | **结果为正，无溢出**      | **成立 (跳转)**                | 正常正数比较（如 $+5 - 0$）         |
| **1**  | **0**  | **1**     | **结果为负，无溢出**      | **不成立 (不跳)**               | 正常负数比较（如 $-5 - 0$）         |
| **1**  | **1**  | **0**     | **结果为负，但==正溢出==** | **成立 (跳转)**                | 实际是极大的正数（如 $+100 - (-50)$） |
| **0**  | **1**  | **1**     | **结果为正，但负溢出**     | **不成立 (不跳)**               | 实际是极小的负数（如 $-100 - (+50)$） |
### 1. 发生了什么？（物理电路视角）
sf=1  of=1  正溢出

假设在 8 位补码系统里（最大能存 $+127$），CPU 执行 `CMP A, B` 比较 $A = +100$ 和 $B = -50$：

1. **ALU 傻傻地做加减法**：
    
    $+100 - (-50)$ 被硬件转换成 $+100 + (+50)$。
    
    二进制相加：`01100100` ($+100$) + `00110010` ($+50$) = `10010110`。
    
2. **硬件看结果发信号**：
    
    - 结果的最高位（第 7 位）变成了 **`1`** $\implies$ **$SF = 1$**（硬件：物理上看，这是个负数，十进制的 $-106$）。
        
    - 两个符号位为 `0` 的正数相加，结果符号位居然变成了 `1` $\implies$ **$OF = 1$**（硬件：糟糕，发生了正溢出！）。
        

### 2. 控制单元怎么判断？（跳转逻辑视角）

如果跳转指令只看符号位 $SF$，CPU 就会得出 $-106 < 0$ 的错误结论（从而认为 $+100 < -50$，不跳转）。

但**有符号数跳转指令（如 `JG`，大则跳转）** 的硬件门电路使用的是逻辑表达式：

$$\text{逻辑符号} = SF \oplus OF$$

在当前情况下：

$$SF \oplus OF = 1 \oplus 1 = \mathbf{0}$$

- **$SF = 1$（物理结果颠倒成了负数）**
    
- **$OF = 1$（硬件记录了“刚才发生了一次颠倒”）**
    
- **异或运算 $1 \oplus 1 = 0$**：恰好利用“负负得正”的逻辑，**把颠倒的符号重新翻转了回来！**
    

### 3. 一句话总结

当结果为物理负数（$SF = 1$）且发生了正溢出（$OF = 1$）时，说明**真实的结果其实是一个超出了数据类型上限的“极大正数”**！

硬件通过 $SF \oplus OF = 1 \oplus 1 = 0$，**成功识破了这个伪装成负数的极大大正数**，从而正确地判定 $A > B$ 成立，顺利执行跳转！



# 4.数据通路？

咱们以 **袁春风教材（408 考研标准）单总线 CPU 结构** 为例，完整拆解一条最典型的“两个数字相加”指令：

$$\text{ADD } R_2, R_1, R_0 \quad (\text{语义：} R_2 \leftarrow R_1 + R_0)$$

> **核心背景说明**：
> 
> 在单总线结构中，ALU 的两个输入端不能同时从总线上拿数据（否则总线冲突）。因此必须：
> 
> 1. 先把第一个加数（$R_1$）拿出来暂存在 **$Y$ 寄存器**；
>     
> 2. 再把第二个加数（$R_0$）放上总线，与 $Y$ 一起送入 ALU 计算；
>     
> 3. 算出的结果先存入 **$Z$ 寄存器**，最后再写回目标寄存器 $R_2$。
>     

### 📘 完整流程：从 PC 取指到结果写回（全生命周期）

下面是从 CPU 取第一条指令开始，到最终把“两个数字之和”写入寄存器 $R_2$ 输出的**完整 7 个节拍（$C_1 \sim C_7$）**：

|**阶段划分**|**节拍**|**微操作（数据流动方向）**|**有效控制信号**|**硬件部件与物理过程说明**|
|---|---|---|---|---|
|**一、取指阶段**<br><br>  <br><br>_(Fetch)_|**$C_1$**|$(PC) \rightarrow MAR$|**`PCout`**, **`MARin`**|PC 内容上总线，送入地址寄存器 MAR。|
||**$C_2$**|$Mem[MAR] \rightarrow MDR$<br><br>  <br><br>$(PC) + 1 \rightarrow PC$|**`MemR`**, **`MDRinE`**, **`PC+1`**|给主存发读信号，指令经外部总线入 MDR；同拍 PC 自动加 1。|
||**$C_3$**|$(MDR) \rightarrow IR$|**`MDRout`**, **`IRin`**|指令从 MDR 上总线打入指令寄存器 IR，译码器开始分析指令。|
|**二、取第一个加数**<br><br>  <br><br>_(Operand 1)_|**$C_4$**|$(R_1) \rightarrow Y$|**`R1out`**, **`Yin`**|译码得知做加法，先开启 $R_1$ 输出，将第一个数字暂存到 **$Y$ 寄存器**。|
|**三、相加运算**<br><br>  <br><br>_(ALU Operation)_|**$C_5$**|$(R_0) + (Y) \rightarrow Z$|**`R0out`**, **`ALUin`**, **`ADD`**, **`Zin`**|$R_0$ 输出上总线，与 $Y$ 的数据一同输入 ALU，ALU 执行加法，结果存入 **$Z$ 寄存器**。|
|**四、写回输出**<br><br>  <br><br>_(Write Back)_|**$C_6$**|$(Z) \rightarrow R_2$|**`Zout`**, **`R2in`**|运算结果从 $Z$ 出发，经内部总线打入目的寄存器 $R_2$，**加法结果输出完成！**|

### 💡 考场高频细节避坑

1. **为什么不需要 $C_7$？**
    
    对于寄存器寻址的算术指令（$R_1 + R_0$），数据都在 CPU 内部，**不需要访问主存取数**，因此在 $C_6$ 拍就把结果写入 $R_2$ 结束了。
    
2. **`MDRinE` 里的 `E` 代表什么？**
    
    代表 External（外部），意思是数据是从 CPU 外部的系统数据总线打进 MDR 的；而在 CPU 内部总线传输时只写 `MDRin` 或 `MDRout`。
    
3. **控制信号的互斥性**：
    
    在同一个节拍内，绝对不能出现两个 `xxxout` 同时有效（比如不能在同一拍写 `R1out, R0out`），因为单总线同一时刻只能容纳一个数据流！
