# 七、I/O 方式

## I/O 方式总览 [混]

| 方式   | CPU 介入程度                 | 数据流向           | 主要硬件    |
| ---- | ------------------------ | -------------- | ------- |
| 程序查询 | 最深入（全程轮询）                | CPU 中转         | 无特殊硬件   |
| 程序中断 | 发命令后做别的，外设就绪后打断          | CPU 中转         | 中断系统    |
| DMA  | 发命令后做别的，外设准备数据后 CPU 让出总线 | 设备 ↔ 内存 **直接** | DMA 控制器 |
| 通道   | CPU 发通道程序即可              | 设备 ↔ 内存 **直接** | I/O 通道  |

**坑点**：==DMA 也是程序中断的一种特例==，但中断方式 CPU 参与数据传输，DMA 不参与。

---

### 程序查询方式 [记][混]

CPU 不断轮询外设状态标志位。

#### 两种查询方式

| 方式       | 含义                    | 特点                |
| -------- | --------------------- | ----------------- |
| **独占查询** | CPU 一直等，啥也不干直到 I/O 完成 | CPU 完全被占用，利用率 0%  |
| **定时查询** | CPU 每隔一段时间查一次状态       | CPU 可抽空干别的，但可能有延迟 |

**坑点**：==独占查询不是中断，是 CPU 死等，期间不执行其他程序==。定时查询是独占查询的改进，但都不是中断。

**特点**：
- CPU 和 I/O 串行工作，CPU 利用率极低
- 接口电路简单，硬件量少
- 用于**早期**或不常用的简单设备

---

### 程序中断方式 [坑][计]

#### 中断分类 [混]

```
中断
├── 内中断（异常/例外）  — CPU 内部产生
│   ├── 故障（Fault）    — 可恢复（缺页、除零）
│   ├── 陷阱（Trap）     — 主动触发（系统调用 int/INT）
│   └── 终止（Abort）    — 不可恢复（硬件错误）
└── 外中断（中断）        — 外设/外部信号
    ├── 可屏蔽中断（INTR） — 可通过 IF 标志屏蔽
    └── 不可屏蔽中断（NMI）— 不可屏蔽（掉电、硬件故障）
```

**坑点**：
- ==内中断（异常）不是"中断"，两者统称"中断"时特指外中断==
- ==内中断不需要中断判优，因为是由 CPU 内部条件直接触发的==
- ==故障（Fault）的断点是出问题那条指令，异常处理完后重新执行==
- ==陷阱（Trap）的断点是下一条指令（如系统调用）==
- ==终止（Abort）不恢复，直接终止当前程序==

#### 中断处理流程 [难]

```
① 中断请求  →  ② 中断判优  →  ③ 中断响应  →  ④ 中断服务  →  ⑤ 中断返回
├── 硬件自动 ──┤                              ├── 软件（中断处理程序）──┤
```

#### ③ 中断响应（硬件自动，逐拍分析）[难]

**背景**：中断响应本质是 CPU 自动执行的一组**隐指令**（不是程序员可用的指令），在指令周期末尾插入。

| 步骤       | 微操作                    | 说明                        |
| -------- | ---------------------- | ------------------------- |
| 1. 关中断   | IF ← 0                 | 硬件自动清除中断标志，阻止新的中断         |
| 2. 保存断点  | (PC) → 栈 / (PC) → 特定地址 | 将当前 PC（及 PSWR）压栈或存到固定地址   |
| 3. 取中断向量 | 中断向量号 → 查中断向量表         | 硬件根据中断请求获取向量号，查表得入口地址     |
| 4. 转中断程序 | PC ← 中断服务程序入口          | 将入口地址赋给 PC，下个指令周期开始执行中断程序 |

**坑点**：
- ==中断响应发生在指令周期末尾（执行阶段结束后）==
- ==保存断点的实质是保存 PC + PSWR（程序状态字寄存器）==
- 隐指令操作的寄存器：PC、MAR、MDR、IR、堆栈指针 SP

**中断响应必须满足的条件**：
1. CPU 处于**开中断**状态（IF = 1）
2. 当前**指令执行完毕**
3. **无 DMA 请求**（DMA 优先级 > 中断）
4. 无更高级中断正被服务

#### ④ 中断服务（软件完成）

```
保护现场 → 开中断(允许嵌套) → 中断处理 → 关中断 → 恢复现场 → 中断返回
├── 软件（中断处理程序完成）───────┤
```

| 步骤       | 说明                          |
| -------- | --------------------------- |
| **保护现场** | 将通用寄存器内容压栈（软件做，区别于硬件只保存断点）  |
| **开中断**  | 允许更高级中断嵌套                   |
| **中断处理** | 执行具体的 I/O 操作                |
| **关中断**  | 准备恢复现场，防止被干扰                |
| **恢复现场** | 从栈中弹出通用寄存器                  |
| **中断返回** | 执行中断返回指令（如 IRET），恢复 PC/PSWR |

**坑点**：==硬件只保存断点（PC/PSWR），通用寄存器的保存和恢复是软件（中断处理程序）做的==。

#### 中断判优 [混]

| 方式   | 速度  | 可改变优先级 | 实现             |
| ---- | --- | ------ | -------------- |
| 链式查询 | 慢   | 否（固定）  | 菊花链 + 固定优先级    |
| 独立请求 | 快   | 是      | 每设备独立请求线，排队器   |
| 中断向量 | 快   | 可编程    | 8259A 可编程中断控制器 |

#### 中断屏蔽 [坑]

- **屏蔽字**：每个中断源对应一个屏蔽字，1 表示屏蔽对应中断
- ==高优先级可以屏蔽低优先级，反之不行（除非修改屏蔽字）==
- 通过修改屏蔽字可以**改变中断处理顺序**（不改变判优优先级）

**坑点**：==中断响应的优先级由硬件判优决定，中断处理的优先级由屏蔽字决定==。

#### 向量中断 vs 非向量中断 [混]

**核心区别**：如何找到中断服务程序入口地址。

| 对比项    | 向量中断                            | 非向量中断                     |
| ------ | ------------------------------- | ------------------------- |
| 入口地址获取 | 硬件**自动**生成中断向量，查**中断向量表**得到入口地址 | 软件**统一查询**，由统一入口程序判断来源再分支 |
| 速度     | 快（硬件直接定位）                       | 慢（需要软件查）                  |
| 硬件成本   | 高（需要中断向量表、向量生成逻辑）               | 低                         |
| 典型应用   | 现代 CPU（x86、ARM）                 | 简单嵌入式 MCU                 |
|        |                                 |                           |

**关键概念**：
- **中断向量**：中断服务程序的入口地址（或地址指针）
- **中断向量表**：所有中断向量组成的表，存放在内存固定区域
- 中断响应阶段：硬件自动关中断 → 保存断点 → **取中断向量** → 转中断服务程序

**坑点**：
- ==向量中断的"取中断向量"是硬件自动完成的，不是软件查的==
- ==中断向量 ≠ 中断向量号==。中断向量号是设备编号，CPU 根据向量号查向量表得到向量（入口地址）
- ==向量中断一定有中断向量表，非向量中断没有中断向量表==

#### 中断嵌套

- **关中断** → 不允许嵌套
- **开中断** → 允许多级嵌套

### DMA 方式 [难][计]

#### DMA 与中断的对比 [混]

| 对比项      | 程序中断      | DMA                |
| -------- | --------- | ------------------ |
| 数据传送     | CPU 中转    | 设备 ↔ 内存直接          |
| 响应时机     | 指令执行完后    | 每个机器周期结束（总线空闲时）    |
| 处理内容     | 各种异常/事件   | 数据块传送              |
| 对 CPU 影响 | 暂停当前程序    | 暂停一个**总线周期**（周期窃取） |
| 优先级      | 低（低于 DMA） | 高                  |
| 异常处理     | 能处理复杂异常   | 仅传数据               |

**坑点**：==中断响应在指令周期末尾，DMA 响应在任意机器周期末尾（总线周期）。DMA 优先级高于中断==。

#### DMA 传送流程

```
CPU 初始化 DMA 控制器（传起始地址、字数、方向）
          ↓
外设准备数据（DMA 请求）
          ↓
DMA 控制器向 CPU 请求总线（总线请求）
          ↓
CPU 让出总线控制权（总线响应）
          ↓
DMA 控制总线，完成数据传送（周期窃取）
          ↓
DMA 传送结束 → 中断通知 CPU
```

#### 三种 DMA 传送方式 [混]

| 方式         | 含义              | 特点               |     |
| ---------- | --------------- | ---------------- | --- |
| **周期窃取**   | DMA 占用一个总线周期    | CPU 暂停一个周期，效率高   |     |
| **块传送**    | DMA 连续占用总线到整块传完 | 数据吞吐量高，CPU 长时间等待 |     |
| **透明 DMA** | 趁 CPU 不用总线时传送   | 对 CPU 无影响，控制复杂   |     |

**坑点**：==周期窃取是 DMA 最常用的方式==。DMA 传送结束后**通过中断通知 CPU**，但此时中断处理不传数据，只做收尾。

---

### 通道方式 [难][记]

**本质**：通道是**有专用处理器的 I/O 控制器**，能执行通道程序。

| 类型 | 特点 | 适用场景 |
|------|------|----------|
| **选择通道** | 一通道一次只服务一台设备，传完才换 | 高速设备（磁盘） |
| **数组多路通道** | 多台设备轮流传数据（以数据块为单位） | 中速设备 |
| **字节多路通道** | 多台设备轮流传字节，交叉执行 | 低速设备（键盘、打印机） |

**坑点**：==通道是硬件不是软件==，通道有自己的指令系统（通道指令），与 CPU 指令不同。

#### 通道与 DMA 的对比

| 对比项 | DMA | 通道 |
|--------|-----|------|
| 控制方式 | 硬件控制器 | 专用处理器（执行通道程序） |
| 灵活性 | 低（固定传送方式） | 高（可编程） |
| 处理能力 | 仅传数据 | 可处理多种 I/O 功能 |
| 并行性 | 一通道对应一设备（数据流） | 一通道可控制多台设备 |

---

### 关键对比总结 [坑]

**五个 I/O 方式的 CPU 忙碌程度**（从高到低）：

```
程序查询 > 中断 > DMA > 通道 > I/O 处理机
```

- ==程序查询：CPU 全程等==
- ==中断：仅传数据时 CPU 参与==
- ==DMA：仅初始化 + 收尾，传数据不参与==
- ==通道：发通道程序就完事==
- ==I/O 处理机：几乎独立运行==

**坑点总结**：
1. DMA 响应时机是在**任意机器周期末尾**检查，不是在指令周期末尾
2. 中断响应是**硬件**做的，中断服务是**软件**做的
3. ==DMA 结束后用中断通知 CPU，但这是"后处理"，不是"数据传输"==
4. 通道有自己的指令系统，不是 CPU 执行的
