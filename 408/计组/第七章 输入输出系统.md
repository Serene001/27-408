# 七、I/O 方式

## I/O 方式总览 [混]

| 方式   | CPU 介入程度                 | 数据流向           | 主要硬件    |
| ---- | ------------------------ | -------------- | ------- |
| 程序查询 | 最深入（全程轮询）                | CPU 中转         | 无特殊硬件   |
| 程序中断 | 发命令后做别的，外设就绪后打断          | CPU 中转         | 中断系统    |
| DMA  | 发命令后做别的，外设准备数据后 CPU 让出总线 | 设备 ↔ 内存 **直接** | DMA 控制器 |
| 通道   | CPU 发通道程序即可              | 设备 ↔ 内存 **直接** | I/O 通道  |

**坑点**：==DMA 也是程序中断的一种特例==，但中断方式 CPU 参与数据传输，DMA 不参与。

---

### 程序查询方式 [记][混]

CPU 不断轮询外设状态标志位。

#### 两种查询方式

| 方式       | 含义                    | 特点                |
| -------- | --------------------- | ----------------- |
| **独占查询** | CPU 一直等，啥也不干直到 I/O 完成 | CPU 完全被占用，利用率 0%  |
| **定时查询** | CPU 每隔一段时间查一次状态       | CPU 可抽空干别的，但可能有延迟 |

**坑点**：==独占查询不是中断，是 CPU 死等，期间不执行其他程序==。定时查询是独占查询的改进，但都不是中断。

**特点**：
- CPU 和 I/O 串行工作，CPU 利用率极低
- 接口电路简单，硬件量少
- 用于**早期**或不常用的简单设备

---

### 程序中断方式 [坑][计]

#### 中断分类 [混]

```
中断
├── 内中断（异常/例外）  — CPU 内部产生
│   ├── 故障（Fault）    — 可恢复（缺页、除零）
│   ├── 陷阱（Trap）     — 主动触发（系统调用 int/INT）
│   └── 终止（Abort）    — 不可恢复（硬件错误）
└── 外中断（中断）        — 外设/外部信号
    ├── 可屏蔽中断（INTR） — 可通过 IF 标志屏蔽
    └── 不可屏蔽中断（NMI）— 不可屏蔽（掉电、硬件故障）
```

**坑点**：
- ==内中断（异常）不是"中断"，两者统称"中断"时特指外中断==
- ==内中断不需要中断判优，因为是由 CPU 内部条件直接触发的==
- ==故障（Fault）的断点是出问题那条指令，异常处理完后重新执行==
- ==陷阱（Trap）的断点是下一条指令（如系统调用）==
- ==终止（Abort）不恢复，直接终止当前程序==

#### 中断处理流程 [难]

```
① 中断请求  →  ② 中断判优  →  ③ 中断响应  →  ④ 中断服务  →  ⑤ 中断返回
├── 硬件自动 ──┤                              ├── 软件（中断处理程序）──┤
```

#### ③ 中断响应（硬件自动，逐拍分析）[难]

**背景**：中断响应本质是 CPU 自动执行的一组**隐指令**（不是程序员可用的指令），在指令周期末尾插入。

| 步骤       | 微操作                    | 说明                        |
| -------- | ---------------------- | ------------------------- |
| 1. 关中断   | IF ← 0                 | 硬件自动清除中断标志，阻止新的中断         |
| 2. 保存断点  | (PC) → 栈 / (PC) → 特定地址 | 将当前 PC（及 PSWR）压栈或存到固定地址   |
| 3. 取中断向量 | 中断向量号 → 查中断向量表         | 硬件根据中断请求获取向量号，查表得入口地址     |
| 4. 转中断程序 | PC ← 中断服务程序入口          | 将入口地址赋给 PC，下个指令周期开始执行中断程序 |

**坑点**：
- ==中断响应发生在指令周期末尾（执行阶段结束后）==
- ==保存断点的实质是保存 PC + PSWR（程序状态字寄存器）==
- 隐指令操作的寄存器：PC、MAR、MDR、IR、堆栈指针 SP

**中断响应必须满足的条件**：
1. CPU 处于**开中断**状态（IF = 1）
2. 当前**指令执行完毕**
3. **无 DMA 请求**（DMA 优先级 > 中断）
4. 无更高级中断正被服务

#### ④ 中断服务（软件完成）

```
保护现场 → 开中断(允许嵌套) → 中断处理 → 关中断 → 恢复现场 → 中断返回
├── 软件（中断处理程序完成）───────┤
```

| 步骤       | 说明                          |
| -------- | --------------------------- |
| **保护现场** | 将通用寄存器内容压栈（软件做，区别于硬件只保存断点）  |
| **开中断**  | 允许更高级中断嵌套                   |
| **中断处理** | 执行具体的 I/O 操作                |
| **关中断**  | 准备恢复现场，防止被干扰                |
| **恢复现场** | 从栈中弹出通用寄存器                  |
| **中断返回** | 执行中断返回指令（如 IRET），恢复 PC/PSWR |

**坑点**：==硬件只保存断点（PC/PSWR），通用寄存器的保存和恢复是软件（中断处理程序）做的==。

#### 中断判优 [混]

| 方式   | 速度  | 可改变优先级 | 实现             |
| ---- | --- | ------ | -------------- |
| 链式查询 | 慢   | 否（固定）  | 菊花链 + 固定优先级    |
| 独立请求 | 快   | 是      | 每设备独立请求线，排队器   |
| 中断向量 | 快   | 可编程    | 8259A 可编程中断控制器 |

#### 中断屏蔽 [坑]

- **屏蔽字**：每个中断源对应一个屏蔽字，1 表示屏蔽对应中断
- ==高优先级可以屏蔽低优先级，反之不行（除非修改屏蔽字）==
- 通过修改屏蔽字可以**改变中断处理顺序**（不改变判优优先级）

**坑点**：==中断响应的优先级由硬件判优决定，中断处理的优先级由屏蔽字决定==。

#### 向量中断 vs 非向量中断 [混]

**核心区别**：如何找到中断服务程序入口地址。

| 对比项    | 向量中断                            | 非向量中断                     |
| ------ | ------------------------------- | ------------------------- |
| 入口地址获取 | 硬件**自动**生成中断向量，查**中断向量表**得到入口地址 | 软件**统一查询**，由统一入口程序判断来源再分支 |
| 速度     | 快（硬件直接定位）                       | 慢（需要软件查）                  |
| 硬件成本   | 高（需要中断向量表、向量生成逻辑）               | 低                         |
| 典型应用   | 现代 CPU（x86、ARM）                 | 简单嵌入式 MCU                 |
|        |                                 |                           |

**关键概念**：
- **中断向量**：中断服务程序的入口地址（或地址指针）
- **中断向量表**：所有中断向量组成的表，存放在内存固定区域
- 中断响应阶段：硬件自动关中断 → 保存断点 → **取中断向量** → 转中断服务程序

**坑点**：
- ==向量中断的"取中断向量"是硬件自动完成的，不是软件查的==
- ==中断向量 ≠ 中断向量号==。中断向量号是设备编号，CPU 根据向量号查向量表得到向量（入口地址）
- ==向量中断一定有中断向量表，非向量中断没有中断向量表==

#### 中断嵌套

- **关中断** → 不允许嵌套
- **开中断** → 允许多级嵌套

### DMA 方式 [难][计]

#### DMA 与中断的对比 [混]

| 对比项      | 程序中断      | DMA                |
| -------- | --------- | ------------------ |
| 数据传送     | CPU 中转    | 设备 ↔ 内存直接          |
| 响应时机     | 指令执行完后    | 每个机器周期结束（总线空闲时）    |
| 处理内容     | 各种异常/事件   | 数据块传送              |
| 对 CPU 影响 | 暂停当前程序    | 暂停一个**总线周期**（周期窃取） |
| 优先级      | 低（低于 DMA） | 高                  |
| 异常处理     | 能处理复杂异常   | 仅传数据               |

**坑点**：==中断响应在指令周期末尾，DMA 响应在任意机器周期末尾（总线周期）。DMA 优先级高于中断==。

#### DMA 传送流程

```
CPU 初始化 DMA 控制器（传起始地址、字数、方向）
          ↓
外设准备数据（DMA 请求）
          ↓
DMA 控制器向 CPU 请求总线（总线请求）
          ↓
CPU 让出总线控制权（总线响应）
          ↓
DMA 控制总线，完成数据传送（周期窃取）
          ↓
DMA 传送结束 → 中断通知 CPU
```

#### 三种 DMA 传送方式 [混]

| 方式         | 含义              | 特点               |     |
| ---------- | --------------- | ---------------- | --- |
| **周期窃取**   | DMA 占用一个总线周期    | CPU 暂停一个周期，效率高   |     |
| **块传送**    | DMA 连续占用总线到整块传完 | 数据吞吐量高，CPU 长时间等待 |     |
| **透明 DMA** | 趁 CPU 不用总线时传送   | 对 CPU 无影响，控制复杂   |     |

**坑点**：==周期窃取是 DMA 最常用的方式==。DMA 传送结束后**通过中断通知 CPU**，但此时中断处理不传数据，只做收尾。

---

### 通道方式 [难][记]

**本质**：通道是**有专用处理器的 I/O 控制器**，能执行通道程序。

| 类型 | 特点 | 适用场景 |
|------|------|----------|
| **选择通道** | 一通道一次只服务一台设备，传完才换 | 高速设备（磁盘） |
| **数组多路通道** | 多台设备轮流传数据（以数据块为单位） | 中速设备 |
| **字节多路通道** | 多台设备轮流传字节，交叉执行 | 低速设备（键盘、打印机） |

**坑点**：==通道是硬件不是软件==，通道有自己的指令系统（通道指令），与 CPU 指令不同。

#### 通道与 DMA 的对比

| 对比项 | DMA | 通道 |
|--------|-----|------|
| 控制方式 | 硬件控制器 | 专用处理器（执行通道程序） |
| 灵活性 | 低（固定传送方式） | 高（可编程） |
| 处理能力 | 仅传数据 | 可处理多种 I/O 功能 |
| 并行性 | 一通道对应一设备（数据流） | 一通道可控制多台设备 |

---

### 关键对比总结 [坑]

**五个 I/O 方式的 CPU 忙碌程度**（从高到低）：

```
程序查询 > 中断 > DMA > 通道 > I/O 处理机
```

- ==程序查询：CPU 全程等==
- ==中断：仅传数据时 CPU 参与==
- ==DMA：仅初始化 + 收尾，传数据不参与==
- ==通道：发通道程序就完事==
- ==I/O 处理机：几乎独立运行==

**坑点总结**：
1. DMA 响应时机是在**任意机器周期末尾**检查，不是在指令周期末尾
2. 中断响应是**硬件**做的，中断服务是**软件**做的
3. ==DMA 结束后用中断通知 CPU，但这是"后处理"，不是"数据传输"==
4. 通道有自己的指令系统，不是 CPU 执行的





| **对比维度**    | **中断 I/O 方式**                                            | **DMA 方式**                           |
| ----------- | -------------------------------------------------------- | ------------------------------------ |
| **数据交换对象**  | **接口寄存器 $\leftrightarrow$ CPU 寄存器 $\leftrightarrow$ 主存** | **接口寄存器 $\leftrightarrow$ 主存**（直接交换） |
| **控制主体**    | **CPU**（通过执行中断服务程序）                                      | **DMA 控制器（硬件）**（接管总线控制权）             |
| **中断发生时机**  | **每传输一个字/字节**就触发一次中断                                     | **一整块数据（如 4KB）**传输完成后才触发一次中断         |
| **CPU 参与度** | 高（CPU 亲自搬运每个数据）                                          | 极低（CPU 只负责预设初始地址和计数器）                |




|**I/O 方式**|**CPU 与外设**|**数据传送与主程序**|**CPU 占用率**|
|---|---|---|---|
|**程序查询方式**|串行（CPU 踏步等待外设）|串行|极高（大量浪费 CPU 时间）|
|**中断方式**|**并行**|**串行**（需 CPU 暂停主程序来传数据）|中等（每次传输都需要 CPU 接管）|
|**DMA 方式**|**并行**|**并行**（DMA 控制器直接传内存，仅抢占总线/周期）|极低（仅在开始和结束时需要 CPU）|




DMA 控制器（DMAC）既不在 CPU 内部，也不在具体的外部设备（如磁盘、网卡）内部，它通常是作为一个独立的硬件模块，连接在系统总线上。
**DMA 请求与响应的独立性**：

- **外设 $\rightarrow$ DMAC**：发出 DMA 请求（DREQ）。
    
- **DMAC $\rightarrow$ CPU**：申请总线控制权（HOLD）。
    
- **CPU $\rightarrow$ DMAC**：让出总线并应答（HLDA）。
    
- **DMAC $\rightarrow$ 外设**：响应外设请求（DACK），开始传送。


|**比较维度**|**中断请求（INTR / INT）**|**DMA 请求（DREQ）**|
|---|---|---|
|**请求发送给谁？**|**CPU**|**DMA 控制器（DMAC）**|
|**请求的本质目的**|请求 CPU 暂停主程序，**执行一段软件程序**（中断服务程序）|请求 DMAC **接管总线**，进行纯硬件层面的数据搬运|
|**CPU 的处理方式**|**执行软件指令**：保护现场 $\rightarrow$ 执行中断程序 $\rightarrow$ 恢复现场|**硬件让出总线**：CPU 内部继续跑，只是暂时不用总线（或挂起总线周期）|
|**响应时机**|**指令周期结束时**（一条指令执行完，CPU 才去查有没有中断）|**总线周期结束时**（响应非常快，不需要等指令执行完）|
|**需要切换上下文吗？**|**需要**（保存 PC、寄存器等断点和现场）|**不需要**（CPU 不需要保存任何软件现场）|



没问题！我们把**单级中断**和**多级中断**的完整处理流程用清晰的流程图画出来，并在关键节点配上详细的注释，方便你对照复习。

## 1. 单级中断（无嵌套）处理流程图

> **核心逻辑**：响应中断后**全程关中断**，即使来更高优先级的任务也只能排队，一干到底再返回。

```
       [ 主 程序 运 行 中 ]
                │
                ▼
      ┌──────────────────┐  ◄─── 1. 指令周期结束时，采样 INTR 信号
      │ 硬件采样中断请求  │
      └─────────┬────────┘
                │
                ▼
     ┌────────────────────┐ ◄─── 2. 中断隐指令（硬件自动完成三件事）：
     │  执行 中断隐指令   │       ① 关中断 (EINT=0)
     └──────────┬─────────┘       ② 保存断点 (PC/PSW 压栈)
                │                 ③ 引出中断服务程序 (PC 赋向量地址)
                ▼
  ┌──────────────────────────┐
  │ 软件: 保护现场 (PUSH)    │ ◄─── 3. 将通用寄存器存入堆栈
  └─────────────┬────────────┘
                │
                ▼
  ┌──────────────────────────┐
  │ 软件: 执行中断服务主体   │ ◄─── 4. 真正干活（如读取外设数据）
  └─────────────┬────────────┘      全程处于关中断状态，绝不被打断！
                │
                ▼
  ┌──────────────────────────┐
  │ 软件: 恢复现场 (POP)     │ ◄─── 5. 还原通用寄存器
  └─────────────┬────────────┘
                │
                ▼
     ┌────────────────────┐ ◄─── 6. 执行中断返回指令 (IRET)：
     │  执行 中断返回指令  │       ① 弹出断点 (恢复 PC/PSW)
     └──────────┬─────────┘       ② 重新开中断 (EINT=1)
                │
                ▼
       [ 返回 被打断的主程序 ]
```

## 2. 多级中断（允许嵌套）处理流程图

> **核心逻辑**：保护好现场后**立刻开中断**；如果有更高的优先级中断过来，直接“递归”再走一遍流程；等高级任务干完了再层层返回。

```
       [ 主 程序 运 行 中 ]  （或 低优先级中断服务程序）
                │
                ▼
      ┌──────────────────┐  ◄─── 1. 硬件比较：新请求优先级 > 当前运行优先级？
      │ 硬件采样中断请求  │
      └─────────┬────────┘
                │
                ▼
     ┌────────────────────┐ ◄─── 2. 中断隐指令（硬件自动完成）：
     │  执行 中断隐指令   │       ① 关中断 (EINT=0) —— 保护后续现场的原子性
     └──────────┬─────────┘       ② 保存断点 (PC/PSW 压栈)
                │                 ③ 引出入口地址 (PC 赋向量地址)
                ▼
  ┌──────────────────────────┐
  │ 软件: 保护现场 (PUSH)    │ ◄─── 3. 保护通用寄存器
  └─────────────┬────────────┘
                │
                ▼
  ┌──────────────────────────┐
  │ 软件: 保存并设置新屏蔽字 │ ◄─── 4. 关键点！屏蔽同级和低级中断，
  └─────────────┬────────────┘      只留下更高级的中断“通行证”
                │
                ▼
  ┌──────────────────────────┐
  │  软件: 开中断 (STI)      │ ◄─── 5. 关键点！正式开启嵌套许可！
  └─────────────┬────────────┘
                │
                ├─────────────────────────────────────────┐
                ▼                                         │ 💡 此时若来高级中断：
  ┌──────────────────────────┐                            │ CPU 暂停当前处理，
  │ 软件: 执行中断服务主体   │                            │ 重新从上面的【步骤1】
  └─────────────┬────────────┘                            │ 递归执行（进入更深层嵌套）
                │                                         │
                ▼                                         │
  ┌──────────────────────────┐ ◄──────────────────────────┘
  │  软件: 关中断 (CLI)      │ ◄─── 6. 干完活了，准备恢复现场，
  └─────────────┬────────────┘      关中断防止还原过程中被打断
                │
                ▼
  ┌──────────────────────────┐
  │ 软件: 恢复旧屏蔽字       │ ◄─── 7. 还原原有的优先级屏蔽状态
  └─────────────┬────────────┘
                │
                ▼
  ┌──────────────────────────┐
  │ 软件: 恢复现场 (POP)     │ ◄─── 8. 还原通用寄存器
  └─────────────┬────────────┘
                │
                ▼
     ┌────────────────────┐ ◄─── 9. 执行中断返回指令 (IRET)：
     │  执行 中断返回指令  │       ① 恢复断点 (PC/PSW)
     └──────────┬─────────┘       ② 重新开中断 (EINT=1)
                │
                ▼
       [ 返回 上一级程序 ]   ◄─── 若刚才发生了嵌套，返回上一级中断；
                                   若没发生嵌套，直接返回主程序。
```

## 💡 考点精讲：为什么多级中断要“关-开-关”折腾三次？

你看多级中断的代码流程，开关中断的切换非常频繁，这就是 408 极其高频的考点：

1. **第一次关中断（硬件自动，中断隐指令完成）**：
    
    - **原因**：CPU 刚刚收到中断，要压栈存 `PC` 和寄存器。如果不关中断，保护现场保到一半被别人打断，堆栈和寄存器就全乱套了。
        
2. **中间开中断（软件指令 `STI`）**：
    
    - **原因**：现场和屏蔽字都已经安全存好了，此时允许更高优先级的紧急任务打断我（实现抢占/嵌套）。
        
3. **第二次关中断（软件指令 `CLI`）**：
    
    - **原因**：主体活干完了，现在要从堆栈里把刚才的屏蔽字和寄存器原值弹出来（恢复现场）。**还原现场的过程同样是不能被打断的临界区**，所以必须再次关中断。
        
4. **最后开中断（硬件自动，中断返回指令完成）**：
    
    - **原因**：一切收拾妥当，返回上一级程序，重新把 CPU 开中断状态恢复，准备接受未来的新中断。




1. **中断指令 ≠ 中断响应**：
    
    - **中断指令**（如 INT 软中断指令）是 CPU **执行阶段**在程序里主动调用的指令，用来主动触发软件中断。
        
    - **中断响应**是 CPU 硬件的一种**周期行为**。当外部硬件发出中断请求（如按键、网卡收包），CPU 硬件在每条指令执行周期的末尾去检测中断引脚，如果符合条件，由**硬件电路（硬件自动）**直接去完成断点保存（如保存 PC/IP 和 PSW/标志寄存器）并跳转到中断服务入口。这个响应过程**不是通过执行某条指令完成的**，而是硬件自动完成的关中断、存断点、送向量等操作。
        
2. **通用寄存器的保护主体与时机**：
    
    - **CPU 硬件（中断响应阶段）**：通常只负责自动保存最关键的控制寄存器（如程序计数器 PC、程序状态字 PSW 等），一般**不会自动帮保护所有的通用寄存器**（如 AX, BX, CX, DX 或 R0-R15 等），因为全部压栈开销太高。
        
    - **通用寄存器的保护**：是在 CPU 硬件跳转到中断服务程序（ISR）之后，由程序员在软件代码的第一时间，通过显式指令（如 `PUSH` / `PUSHA` 等）手动将用到的通用寄存器压入堆栈保护起来的。
        


| **保存的信息内容**            | **保存的主体（谁来做）**  | **存放在什么物理介质/区域**     | **典型的保存指令/动作**      |
| ---------------------- | --------------- | -------------------- | ------------------- |
| **程序断点 (PC/IP)**       | **CPU 硬件自动**    | 系统堆栈 (Stack)         | 硬件控制单元自动压栈          |
| **程序状态字 (PSW/EFLAGS)** | **CPU 硬件自动**    | 系统堆栈 (Stack)         | 硬件控制单元自动压栈          |
| **通用寄存器 (R0~R15等)**    | **中断服务程序 (软件)** | 系统堆栈 (Stack)         | `PUSH` / `PUSHA` 指令 |
| **中断向量/中断号**           | **中断控制器 (硬件)**  | 控制器内部寄存器             | 硬件锁存并通过总线传送         |
| **外设原始数据/状态**          | **外部设备 (硬件)**   | 外设内部 Register / FIFO | 外设硬件锁存，等待 CPU 读取    |




### 一句话总结

中断响应是**硬件自动行为**，只负责保护断点（PC/PSW 等）；而通用寄存器的保护是在进入中断服务程序后，由软件（程序员写的指令）去执行保护的。



- **外设 $\rightarrow$ 中断控制器**：发送 **中断请求（IRQ）**
    
- **中断控制器 $\rightarrow$ CPU**：发送 **中断请求（INTR）**
    
- **CPU $\rightarrow$ 中断控制器**：处理完后发送 **中断结束信号（EOI）**



CPU 检测（采样）中断请求的时机，可以精准定位在 **每条指令执行周期的末尾**（也就是 **执行阶段结束后、取下一条指令之前** 的专门阶段，通常称为 **中断采样阶段** 或 **中断周期**）。




# 计算cpu用于IO占比

这三种 I/O 方式在计算 **CPU 用于 I/O 的时间占比** 时，核心差异在于：**CPU 到底在哪些环节被占用了时间**。

计算的核心公式永远是：

$$\text{CPU 时间占比} = \frac{\text{1秒内 CPU 专门处理该 I/O 所消耗的总时间 (秒)}}{1 \text{ 秒}} \times 100\%$$

我们假定一个统一的标准场景：

- 外设传输速率为 $D$ （如：每秒传输 1,000 个字）。
    
- 时钟周期/时间单位统一折算为秒。
    

### 1. 程序查询方式（轮询/POLL）

#### 占用原理

CPU **全程参与**。从外设开始准备数据（如磁盘寻道、键盘等待），到检测状态，再到数据搬运，CPU 都在跑查询循环，无法做任何其他事情。

#### 计算公式

如果外设准备好一个数据并完成传送需要耗时 $T_{\text{Cycle}}$，或者 CPU 在整个传输过程中完全处于死等状态：

$$\text{1秒内 CPU 占用时间} = \text{数据传输完全耗费的总时间}$$

> **典型计算形式（考研大题常见）：**
> 
> 只要外设一直在进行数据传输，CPU 的时间就会被 **100%** 占用在查询和等待上。
> 
> $$\text{CPU 时间占比} = 100\%$$
> 
> _(注：除非题目明确给出外设不是连续工作，而是隔一段时间才工作一次，此时占比 $= \frac{\text{外设工作时间}}{\text{总时间}}$)_

### 2. 中断方式（INTERRUPT）

#### 占用原理

CPU **省去了“等待外设准备”的时间**，但**保留了“每次数据准备好后的搬运和中断处理”时间**。

每一次传输数据（如 1 个字节/字），外设都会发一次中断。CPU 必须响应中断，执行**保护现场 $\rightarrow$ 传输数据 $\rightarrow$ 恢复现场**的全套程序。

#### 计算公式

$$\text{1秒内 CPU 占用时间} = \text{1秒内产生的中断次数} \times \text{单次中断服务程序消耗的时间}$$

- **1秒内中断次数**：等于外设 1 秒内传输的数据块/字/字节数。
    
- **单次中断时间**：包括硬件响应开销 + 软件服务程序（`PUSH`、`IN/OUT`、`MOV`、`POP`、`IRET` 等指令执行时间的总和）。
    

$$\text{CPU 时间占比} = \left( \text{每秒传输次数} \times \text{单次中断处理时间 (秒)} \right) \times 100\%$$

### 3. DMA 方式（直接内存访问）

#### 占用原理

数据直接在外设与内存之间通过 DMA 控制器搬运，**数据传送过程完全不占用 CPU**。

CPU 仅在以下两个极其微小的节点被占用：

1. **预处理阶段**：CPU 执行几条指令向 DMA 控制器写入传送方向、内存首地址、传送字数等参数（占用极少）。
    
2. **后处理阶段**：整块数据（如一个 4KB 扇区/数据块）传送完毕后，DMA 发出一个中断，CPU 执行中断服务程序做收尾工作。
    
3. _(系统结构考点)_：在传送过程中，如果发生 CPU 与 DMA **争抢总线/内存访存**，会存在“单字传送时的总线窃取/周期挪用”（占用 1 个存取周期）。
    

#### 计算公式（考研标准算例）

对于成块（Block）传输的数据：

$$\text{1秒内 CPU 占用时间} = \text{1秒内传送的数据块数} \times \text{单次 DMA 后处理中断的时间}$$

$$\text{CPU 时间占比} = \left( \frac{\text{每秒传输总数据量}}{\text{单个数据块大小}} \times \text{单次 DMA 中断处理时间 (秒)} \right) \times 100\%$$

> **如果考题考虑“周期挪用（窃取存取周期）”：**
> 
> 还需要加上 DMA 挪用总线对 CPU 造成的访存延迟开销：
> 
> $$\text{总 CPU 占用时间} = \text{DMA 中断收尾时间} + (\text{1秒内传输的字数} \times \text{主存存取周期})$$

### 💡 三者直观对比总结

假设 1 秒内传输 1,000 个字的数据：

| **I/O 方式** | **CPU 在干什么？**                      | **CPU 1秒内被占用的时间计算**             | **典型占用率数量级**         |
| ---------- | ---------------------------------- | ------------------------------- | -------------------- |
| **程序查询**   | 死等 1,000 次数据准备 + 搬运 1,000 次        | 全程等待时间 + 搬运时间                   | **100%** （极高）        |
| **中断方式**   | 做别的事；每来 1 个字，被打断 1 次去搬运            | $1000 \times \text{单次中断服务时间}$   | **0.1% ~ 5%** （较低）   |
| **DMA 方式** | 做别的事；等 1,000 个字**全部传完**，才被打断 1 次收尾 | $1 \times \text{单次 DMA 中断服务时间}$ | **0.001% 甚至更低** （极低） |
|            |                                    |                                 |                      |

这种对比也是 408 计组大题中最经典的考点，做题时只要抓住 **“1秒内发生多少次处理”** 和 **“单次处理花多少时间”** 相乘，逻辑就不会错！




### 一、 算一笔账：整体利用率是怎么拉低到 1% 的？

假设我们要从磁盘读取 **1 KB** 的数据，磁盘每准备 1 个字节需要 **100 微秒（$\mu s$）**，而 CPU 进中断处理程序去搬运这 1 个字节只需要 **1 微秒（$\mu s$）**。

我们来看这 100 微秒的时间里发生了什么：

Plaintext

```
时间轴 (共 100 微秒)：
|-- 1 μs --|---------------------- 99 μs ----------------------|
[执行中断程序] [                  CPU 在跑其他程序                  ]
 [搬数据 1B]   [           （如：Word 软件、播放音乐等）            ]
```

1. **第 0 ~ 1 微秒：** 收到中断，CPU 进中断处理程序，花费 $1\,\mu s$ 搬运了 1 个字节的数据。
    
    - 这 $1\,\mu s$ 里，CPU 满载（100%）。
        
2. **第 1 ~ 100 微秒：** 中断程序立刻结束并返回。在接下来的 $99\,\mu s$ 里，磁盘在慢慢准备下一个字节，而 **CPU 切回去继续跑别的软件（比如写文档、听歌）**。
    

#### 那 CPU 在“磁盘读取”这件事上的占用率是多少？

如果专门统计 CPU 为这个 I/O 操作服务的时间：

$$\text{I/O 的 CPU 占用率} = \frac{\text{中断处理耗时}}{\text{总周期时间}} = \frac{1\,\mu s}{100\,\mu s} = 1\%$$

剩下的 **99% 的时间**，CPU 完全是自由的，可以用来跑其他任何程序！

**如果外设请求中断的频率太高，高到超过了 CPU 处理中断的速度，CPU 确实会被吃满（100%），甚至直接崩溃！**

用一句话总结你的推论：**如果外设数据准备得比 CPU 还要快，CPU 会一直在接中断、跑中断，啥别的都干不了，占用率直接飙到 100%。**

计算机科学里对你说的这种极端现象有一个专门的术语，叫 **“中断风暴”（Interrupt Storm）**。


# 异步通信必有 1 位起始位



| **阶段**     | **线路电平**    | **接收方动作**            |
| ---------- | ----------- | -------------------- |
| **空闲状态**   | 高电平 (1)     | 保持等待                 |
| **起始位**    | **低电平 (0)** | **检测到下降沿，重置时钟，准备采样** |
| **数据/校验位** | 0 或 1       | 在每个 Bit 周期的中间位置精准采样  |
| **停止位**    | 高电平 (1)     | 恢复高电平，确保下一次起始位能产生下降沿 |

所以，异步通信中的**起始位（低电平 0）**配合**空闲/停止位（高电平 1）**，构成了低成本通信中最简洁、高效的硬同步机制！




中断响应阶段（由硬件隐指令完成）主要进行以下三项核心操作：

1. **关中断**：将允许中断触发器（IF）置 0，防止新的中断打扰当前的中断响应。
    
2. **保护断点和现场**：将当前程序计数器（PC）和状态寄存器（PSWR）的内容压入堆栈保存，以便中断处理完后能正确返回。
    
3. **中断识别/引出中断服务程序**：识别中断源，获取中断服务程序的入口地址（形成向量地址/送入 PC），转去执行中断服务程序。
